**Analytical Breakdown**

**I. Login Page Design & UI Rules**

*   **Initial State:** The current login page is deemed too cluttered and generic.
*   **Login Fields:**
    *   **Removal:** "Institutional Handle," "Registered Email," "Username" fields are to be removed. "Secure Gateway" text/element also to be removed or deprioritized.
    *   **Consolidation:** The primary login field should be simplified to accept either "UID" or "EMP ID".
    *   **Placeholder Text:** The field should display "Registered UID / EMP ID".
*   **Validation:**
    *   **UID:** Strict validation for 13 digits (as per assumed standard).
    *   **EMP ID:** Strict validation for 8 or 9 digits (as per assumed standard).
    *   **Purpose:** To ensure correct input format and prevent errors.
*   **Buttons/Links:**
    *   **"Forgot Password" Button:** To be added.
    *   **"Contact Admin" Button:** To be added.
*   **Flip Cards (Animation & Content):**
    *   **Mechanism:** When "Forgot Password" or "Contact Admin" is clicked, the login card should "flip" like a coin to reveal a new interface.
    *   **"Forgot Password" Flip Card:**
        *   **Content:** "Forgot Password" title, "Enter Your UID or EMP ID" field, and a "Send Details" button.
        *   **Functionality:** Upon clicking "Send Details," the system will send login details (password/OTP) via any enabled OTP mode (Email, WhatsApp, SMS) to the user.
        *   **Confirmation Message:** After sending details, the card should flip back to the login page, displaying a message like "Please check your SMS / WhatsApp / Email for your password."
        *   **Theme:** Orange theme for this card.
    *   **"Contact Admin" Flip Card:**
        *   **Content:** "Contact Admin" title, "Your UID or Employee ID" field, a "Regarding" dropdown, and a text area for "Concern."
        *   **"Regarding" Dropdown Options:** "Username / Password," "Username," "Password," "Others."
        *   **Functionality:** Upon "Submit," a ticket is generated in the Admin Panel.
        *   **Theme:** Blue theme for this card.
*   **Login Source (Ticket Generation):**
    *   **Purpose:** To track where a support ticket originated.
    *   **Implementation:** When a ticket is generated from the "Contact Admin" form on the login page, a "Source" field in the ticket's database entry will be populated with "Login Page."
    *   **Benefit:** Allows administrators to filter and analyze issues specifically related to the login process.

**II. Dashboard Card Design & Layout Rules (Admin Login - Institution Console)**

*   **Overall Structure:** The dashboard will display key metrics in a card-like format. The data shown will be "as per role" (e.g., Admin sees more).
*   **Top-Level Session Indicator:**
    *   **Placement:** The current academic session (e.g., "25-26") should be prominently displayed at the top of the dashboard.
    *   **Visual Emphasis:** The text for the current session should be larger and have an **orange color** to make it highly visible and immediately clear to the user which term they are viewing.
    *   **Functionality:** Clicking this element should allow changing the session, which would then display data for the selected previous session.
    *   **Removal:** The existing "Session" menu item in the second menu should be removed, as the top-level indicator replaces its function.
    *   **Removal:** Any "affiliated with" or similar institutional identification text should be removed as it's redundant.
*   **Dashboard Cards:**
    1.  **Enroll Scholars (Total Students):**
        *   **Title:** "Enroll Scholars" (or "Total Students").
        *   **Primary Metric:** Total number of *active* students.
        *   **Drill-down (on click):** Clicking this card will open a detailed table view.
            *   **Table Content:** Department-wise breakdown of students.
            *   **Columns:** Department Name, Active Students, Deactive Students, Struck-off Students, Total.
            *   **Department Examples:** Computer Science, Mechanical, School of Engineering, School of Commerce, Arts, etc.
            *   **Totals:** An overall total for "Active," "Deactive," and "Struck-off" students should be displayed at the *very top* of this detailed view (not at the bottom of the table).
            *   **Percentage Calculation:** Each numerical value (Active, Deactive, Struck-off for each department, and their totals) should be accompanied by its percentage in small font within brackets.
            *   **Purpose of Percentages:** To quickly identify trends, e.g., which department has the highest percentage of deactivated or struck-off students.
            *   **Navigation:** Clicking a specific department's row in the table would likely lead to a further drill-down (though not explicitly stated, implied by "dashboard wapis aa jayega pura purana" when clicking back).
    2.  **Total Staff:**
        *   **Title:** "Total Staff."
        *   **Breakdown:** Display staff numbers categorized as:
            *   Administration
            *   Teaching
            *   Non-Teaching
        *   **Presentation:** The numbers should be shown with plus signs, e.g., "40 (Admin) + 500 (Teaching) + 200 (Non-Teaching) = Total Staff."
    3.  **Faculty Student Ratio:**
        *   **Title:** "Faculty Student Ratio."
        *   **Metric:** Display the average faculty-student ratio.
    4.  **Revenue Forecast:**
        *   **Title:** "Revenue Forecast."
        *   **Metric:** Display the total amount of pending fees (expected future revenue).
        *   **Exclusion:** "Realized" revenue is not relevant for this card as management is interested in future income.

**III. General UI/UX Principles**

*   **Simplicity:** Remove unnecessary elements from the login page to make it cleaner.
*   **Clarity:** Use clear labels for input fields (e.g., "Registered UID / EMP ID").
*   **Visibility:** Use color (orange) and larger font size to highlight critical information (current session).
*   **Intuitive Navigation:** Flip animations for password/admin contact, and clear drill-down paths for dashboard data.
*   **Data-Driven Insights:** Present data with percentages to provide quick analytical insights into student status and departmental performance.
*   **Role-Based Access:** Dashboard content should adapt based on the user's role.
